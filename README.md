# Е2 Екологія · що на коли

Спільний календар групи: заняття, дедлайни/ДЗ і новини. Без реєстрації: додавати й редагувати може кожен, хто має посилання,
а кожна зміна пишеться в журнал, звідки її можна повернути.

Стек: Go (`net/http` + `pgx`) і PostgreSQL. UI — статичні HTML/CSS/JS, вбудовані в бінарник через `go:embed`.
На виході один процес.

## Локальний запуск

```sh
docker compose up --build
```

Відкрити http://localhost:8080. Під час першого старту міграції створюють таблиці й заливають осінній розклад
(`internal/db/migrations/002_seed_schedule.sql`).

Без Docker для застосунку (Postgres усе одно потрібен):

```sh
docker compose up -d db
DATABASE_URL=postgres://tasks:tasks@localhost:5432/tasks?sslmode=disable go run ./cmd/server
```

## Деплой: DigitalOcean App Platform + Neon

Застосунок працює на App Platform (`.do/app.yaml`: сервіс із `Dockerfile`, 1 vCPU / 512 МБ, $5/міс, Франкфурт,
автодеплой на push у `main`). База — безкоштовний Postgres у [Neon](https://neon.tech).

Чому не dev-база DigitalOcean: її користувач не має права створювати таблиці (`permission denied for schema public`)
і навіть власну схему (`permission denied for database`), тож міграції не проходять.

**База (Neon):**
1. [console.neon.tech](https://console.neon.tech) → Create project, регіон **AWS Europe Central 1 (Frankfurt)**.
2. Connect → **вимкнути Connection pooling** (пряме підключення) → скопіювати рядок
   `postgresql://…neon.tech/neondb?sslmode=require`.

**Застосунок (DigitalOcean):**
1. Apps → Create App → GitHub → `zh0glikk/tasks-manager`, гілка `main`.
2. Settings → App Spec → Edit → вставити `.do/app.yaml`, підставивши свій рядок Neon у `DATABASE_URL`
   (`type: SECRET`, тому DO зберігає його зашифрованим). Створення з GitHub не читає `.do/app.yaml` само.
3. Save → після деплою в Runtime Logs має бути `migrations applied`.

Міграції запускаються у фоні з повторами: сервер і `/healthz` піднімаються одразу, а `/api/*` відповідає 503, доки
міграції не застосуються. Якщо в базі немає права писати в `public`, сервер пробує створити й використовувати схему `app`.

Свій домен: App → Settings → Domains.

## Хто може редагувати сайт

Читати сайт може будь-хто. Редагувати (додавати, змінювати, видаляти, повертати зміни) можна тільки з
**ключем із Telegram-бота, у якого є право запису**: ключ видає `/key`, а право дає адмін через `/grant`.
Перевірка та сама, що для MCP: ключ активний і людина досі в основному чаті групи.

- Вхід: кнопка «Увійти» на сайті і ключ, або посилання «увійти одним кліком», яке бот додає до `/key` для
  власників права запису (`https://…/#key=e2_…`). Ключ іде в `#`-частині адреси, тому не потрапляє в логи
  сервера. Сайт одразу прибирає його з адресного рядка й зберігає в браузері.
- Без права запису кнопок редагування на сайті не видно. API відповідає 401 без ключа і 403 з ключем на перегляд.
- Автор у журналі змін береться з ключа, тож підписатися чужим ім'ям не вийде.
- Обмеження частоти: 30 запитів на запис за хвилину з однієї IP-адреси.
- Локально (`docker compose`) стоїть `OPEN_EDITING=true`, тобто редагування без ключа. На проді цю змінну **не задавай**.
  Щоб перевірити вхід локально: `OPEN_EDITING=false docker compose up --build`, а ключ створи командою
  `docker compose exec app /app keys create "Ім'я"`.

## Telegram-бот і MCP для Claude

**Бот** працює через long polling (вебхук не потрібен) і може бути в кількох чатах групи (загальний, з окремого
предмета тощо). Усі вони наповнюють один календар:
- бота додали в новий чат → адміни отримують запит в особисті. Варіанти відповіді:
  - `/allow ID`: **основний** чат. Учасники отримують ключі, тут працюють `/today` і `/week`, сюди приходять нагадування;
  - `/allow ID watch`: чат **для спостереження** (наприклад, спільний з іншими групами). Переписка зберігається
    й доступна через Claude лише тим його учасникам, у кого вже є ключ з основного чату. Ключів, команд і нагадувань тут немає;
  - `/deny ID`: заборонити. Уже збережена переписка видаляється.
  Поки чат не дозволено, бот його не зберігає й не відповідає там. Після `/allow` бот сам пише в чат, що він
  зберігає і хто може це читати;
- якщо група стає супергрупою (у неї змінюється id), бот переносить статус та історію на новий id сам;
- зберігає текстові повідомлення чату `CHAT_RETENTION_DAYS` днів (за замовчуванням 14), потім видаляє;
- `/today`, `/week` у чаті, а о 20:00 (Київ) нагадує про завтрашні дедлайни;
- за 10 хвилин до пари і в момент її початку пише адмінам в особисті (назва, час, викладач, посилання).
  Розклад тримається в пам'яті без строку дії: читається з бази при старті і перечитується лише після зміни
  занять чи предметів (store повідомляє бота через `OnChange`), тож щохвилинна перевірка базу не чіпає;
- в особистих `/key` видає персональний MCP-ключ учаснику будь-якого основного чату (перевіряє через
  `getChatMember`). Ключ один на людину і без строку дії: повторний `/key` показує той самий
  ключ, новий видається лише після `/revoke`. Ключі відкликаються, коли людина виходить з усіх основних чатів (подія від
  Telegram). Якщо ж перевірка членства під час запиту не пройшла, запит відхиляється, але ключ лишається, тож
  після повернення в чат чи збою Telegram він знову працює. Помилки рівня чату («chat not found», «upgraded to
  a supergroup») не вважаються виходом людини. Через MCP кожен бачить
  переписку **тільки тих чатів, де він сам є**;
- **ключ за замовчуванням дає тільки читання.** Право запису дає адмін: `/grant ID` (ID ключа з `/keys`), а
  `/ungrant ID` його забирає. Право прив'язане до людини і зберігається при перевипуску ключа. Адміни пишуть завжди;
- меню команд («/») бот реєструє сам: окремо для груп, для особистих і для адмінів; Членство перевіряється ще й під час кожного звернення до MCP
  (кеш на 10 хв), тож ключ не працюватиме, навіть якщо бот пропустив подію виходу;
- для адмінів (`TELEGRAM_ADMIN_IDS`) є `/chats`, `/allow ID [watch]`, `/deny ID`, `/reminders ID on|off`
  (нагадування йдуть в основні чати, якщо їх не вимкнено), `/keys`, `/grant ID`, `/ungrant ID` і `/revokekey ID`.

**MCP** живе на `/mcp` (streamable HTTP, stateless), доступ за заголовком `Authorization: Bearer e2_…`.
- Інструменти: `chats`, `chat_messages`, `calendar`, `upcoming_deadlines`, `news`, `courses`, `recent_changes`,
  `lectures`, `lecture_transcript`, `search_lectures`, `add_deadline`, `update_deadline`, `add_news`, `add_event`,
  `update_lecture`. Інструментів для видалення немає.
- Ключ шукається за SHA-256. Ключі з Telegram зберігаються ще й як є (`key_plain`), щоб `/key` міг
  показати той самий: вони відкривають лише дані з цієї ж бази. Ключі з консолі зберігаються тільки як хеш. Кожен виклик пишеться в `mcp_access`, а зміни потрапляють у журнал
  змін з автором «Ім'я (через Claude)».
- Ліміти: 120 викликів на хвилину на ключ і 300 на IP.

Інструкція для учасників групи: [docs/CLAUDE.md](docs/CLAUDE.md).

**Налаштування:**
1. @BotFather → `/newbot`, потім `/setprivacy` → Disable (інакше бот бачить лише команди). Додай бота в чат групи.
2. Напиши боту в особисті `/chatid`, щоб дізнатися свій user id, і впиши його в `TELEGRAM_ADMIN_IDS`. Після
   цього кожен новий чат з ботом приходитиме тобі на підтвердження.
3. Змінні в DigitalOcean (App → Settings → web → Environment Variables):

| Змінна | Приклад | Примітка |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | `123:ABC…` | **Encrypt**. Без неї бот вимкнений, а MCP працює з ключами з CLI |
| `TELEGRAM_CHAT_ID` | `-1001234567890` | необов'язково: основний чат, дозволений одразу (інші — через `/allow`) |
| `TELEGRAM_ADMIN_IDS` | `111,222` | хто бачить `/keys` |
| `PUBLIC_URL` | `https://clownfish-app-lpt6d.ondigitalocean.app` | для посилань і команди підключення |
| `CHAT_RETENTION_DAYS` | `14` | скільки днів зберігати повідомлення |

Імпорт історії чату (бот бачить повідомлення лише з моменту, коли його додали): у Telegram Desktop відкрий
чат → ⋮ → Export chat history → формат JSON, без медіа. Потім виконай
`/app import-telegram result.json [--watch]`. Команда дозволить чат (основним або для спостереження) і додасть
повідомлення, старші за перше, яке бот уже зберіг сам, тож дублів не буде і повторний запуск безпечний.
Локально проти продової бази:
`docker run --rm --env-file .env -v "$PWD/result.json":/data/result.json:ro <образ> /app import-telegram /data/result.json`
(у `.env` має бути `DATABASE_URL`). `result.json` і `.env` у git не потрапляють.

Ключ без Telegram (для себе чи для тестів): у DO відкрий App → Console і виконай
`/app keys create "Ім'я" [--read]`, а також `/app keys list` і `/app keys revoke ID`.

Тести (потрібен Postgres): `TEST_DATABASE_URL=postgres://… go test ./...`. Вони проганяють бота з фейковим
Telegram API і справжнього MCP-клієнта.

## Записи лекцій і транскрипти

Відео лишається там, куди його виклали (YouTube, Google Drive, Zoom, Telegram). На сервері зберігаються тільки
посилання, транскрипт із таймкодами (`lecture_segments`) і конспект. Читати записи може кожен, як і решту
сайту; додавати й змінювати їх можна з ключем, що має право запису.
- На сайті є розділ «Записи лекцій» з пошуком по всіх транскриптах. Якщо у запису є посилання на YouTube, клік
  по таймкоду відкриває відео з цього місця. У панелі дня біля пари, до якої є запис, з'являється «Запис і транскрипт»:
  запис прив'язується до пари через `event_id` або збігом дати й предмета.
- У журнал змін потрапляють тільки поля запису, без транскрипту.
- Конспект зручно робити через Claude: «зроби конспект лекції #3 з таймкодами і збережи» (інструмент `update_lecture`).

**Розпізнавання працює локально** (на M-серії Mac година запису обробляється за кілька хвилин). Потрібні
`brew install ffmpeg whisper-cpp yt-dlp` і модель
[ggml-large-v3-turbo.bin](https://huggingface.co/ggerganov/whisper.cpp/tree/main) у `~/.cache/whisper-models/`.

```sh
export E2_URL=https://адреса-сайту E2_KEY=e2_…   # ключ із правом запису

# за посиланням: yt-dlp сам бере назву й дату (дату можна змінити через -date)
go run ./cmd/lecture -url 'https://www.youtube.com/watch?v=…' -course 3

# локальний файл (наприклад, збережений з Telegram Desktop)
go run ./cmd/lecture -file пара.mp4 -date 2026-10-23 -title 'Методологія: лекція 4' -course 1 -event 42 \
  -video-url 'https://t.me/c/…/123'
```

Інші прапорці: `-transcript FILE.json` бере готовий JSON від whisper.cpp, `-out FILE` зберігає запит замість
завантаження. Whisper часом пише «диссертація» чи «доброчисність»; такі помилки утиліта виправляє сама.
Підказка `-prompt` з правильним написанням допомагає менше і може змусити whisper повторювати вигадані фрази,
тому за замовчуванням її немає. id предметів видно в MCP-інструменті
`courses`, id пар в інструменті `calendar`.

## Структура

```
cmd/server/            точка входу: конфіг, міграції, HTTP-сервер
cmd/lecture/           локальне розпізнавання запису і завантаження транскрипту
internal/db/           підключення і вбудовані SQL-міграції
internal/store/        запити до БД, журнал змін, відкат
internal/api/          JSON API, вхід за ключем
internal/validate/     перевірка даних (спільна для API і MCP)
internal/keyauth/      перевірка ключів (спільна для сайту і MCP)
internal/telegram/     бот: збереження чату, ключі, /today, нагадування
internal/mcpserver/    MCP-сервер для Claude
internal/e2e/          інтеграційні тести бота і MCP
docs/CLAUDE.md         як учасникам підключити Claude
web/static/            UI (index.html, style.css, app.js)
```

## API

| Метод | Шлях | Що робить |
|---|---|---|
| GET | `/api/courses` | предмети |
| GET | `/api/events?from=YYYY-MM-DD&to=YYYY-MM-DD` | заняття за період |
| GET | `/api/assignments?from=…&to=…` | дедлайни за період |
| GET | `/api/posts?limit=30` | новини (закріплені першими) |
| POST / PUT / DELETE | `/api/{courses,events,assignments,posts}[/{id}]` | створити / змінити / видалити |
| GET | `/api/lectures[?course_id=]` | записи лекцій |
| GET | `/api/lectures/{id}` | запис і його транскрипт |
| GET | `/api/lectures/search?q=…` | пошук у транскриптах |
| POST / PUT / DELETE | `/api/lectures[/{id}]` | додати запис із полем `transcript` / змінити / видалити |
| GET | `/api/changes?limit=50` | журнал змін |
| POST | `/api/changes/{id}/revert` | повернути зміну |

Усі запити на запис приймають JSON з полем `author`. `POST /api/events` з полем `repeat_until` створює щотижневу серію.
Видалення м'яке: рядок отримує `deleted_at`, і його можна відновити з журналу.
